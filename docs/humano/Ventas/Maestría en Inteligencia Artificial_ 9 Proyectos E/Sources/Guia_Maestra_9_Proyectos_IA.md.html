PROYECTO 1: PIPELINE DE TRABAJO MULTI-IA

Concepto: Una IA planifica → otra ejecuta → otra revisa el resultado.

¿Qué es esto en términos simples?

PROYECTO 2: COMUNICACIÓN ENTRE 2 IAs CON DOCUMENTOS

Concepto: IA-Abogado con sus documentos legales + IA-CEO con sus documentos de negocio. Dialogan y llegan a conclusiones.

¿Qué es esto en términos simples?

Tienes dos expertos virtuales. Cada uno ha leído carpetas diferentes de documentos. Los pones a conversar. El abogado dice "este contrato tiene riesgo X", el CEO responde "pero necesitamos ese deal por Y", y van negociando hasta llegar a una conclusión. La clave técnica es RAG (Retrieval-Augmented Generation): antes de responder, cada IA busca en sus documentos la información relevante.

ChromaDB es esa biblioteca — convierte tus documentos en números (vectores) que la IA puede buscar súper rápido. Instrucciones:

  2. Preparar documentos: Pon los docs del abogado en una carpeta (/docs/legal/) y los del CEO en otra (/docs/negocio/).

import ollama
import json

def analizar_propiedad(ruta_imagen):
    prompt = """Analiza esta imagen de propiedad inmobiliaria y responde en JSON:
    {
      "estilo_arquitectonico": "contemporáneo/colonial/minimalista/etc",
      "paleta_colores": ["color1", "color2", "color3"],
      "colores_hex": ["#xxx", "#xxx", "#xxx"],
      "atributos_destacados": ["atributo1", "atributo2"],
      "estado_conservacion": "excelente/bueno/regular/necesita remodelación",
      "nivel_acabados": "lujo/medio-alto/medio/económico",
      "tipo_espacio": "sala/recámara/cocina/exterior/fachada",
      "iluminacion": "natural abundante/moderada/artificial",
      "puntos_venta": ["punto1", "punto2"],
      "areas_mejora": ["area1", "area2"]
    }"""
    
    response = ollama.chat(
        model='llava:13b',
        messages=[{
            'role': 'user',
            'content': prompt,
            'images': [ruta_imagen]
        }]
    )
    return response['message']['content']

# Uso
resultado = analizar_propiedad("foto_departamento.jpg")
print(resultado)

from PIL import Image
from collections import Counter
import numpy as np

def extraer_paleta(imagen_path, n_colores=5):
    img = Image.open(imagen_path).resize((150, 150))
    pixels = np.array(img).reshape(-1, 3)
    # Cuantización simple
    pixels = (pixels // 32) * 32  # Agrupar colores similares
    counter = Counter(map(tuple, pixels))
    return [f"#{r:02x}{g:02x}{b:02x}" for (r,g,b), _ in counter.most_common(n_colores)]

PROYECTO 4: REBOTE DE IDEAS ENTRE 2 IAs

Concepto: Dos IAs debaten, enriquecen y refinan ideas entre sí.

¿Qué es esto en términos simples?

En vez de tú hablar con UNA IA, pones a DOS IAs a conversar. Una propone, la otra critica y mejora, la primera responde. Después de varias rondas, las ideas son más refinadas que lo que una sola IA produce.

TIER 1: LOW COST ($0)

Método más simple y efectivo — SIN código:

  1. Abre Claude Pro en una pestaña
  2. Abre Gemini Pro en otra pestaña
  3. Dale a cada uno un rol y personalidad diferente
  4. Copia la respuesta de uno y pégala como input del otro
  5. Repite 5-10 rondas Esto no es broma — es altamente efectivo porque:
  • Modelos diferentes tienen sesgos diferentes → se complementan
  • Claude es más analítico, Gemini más creativo
  • ChatGPT Go te da una tercera perspectiva Para automatizarlo localmente (gratis):
import ollama

def debate(tema, rondas=5):
    historial = f"TEMA: {tema}\n"
    
    for i in range(rondas):
        # IA Optimista (Qwen)
        resp1 = ollama.chat(model='qwen2.5:7b', messages=[{
            'role': 'user',
            'content': f"""Eres un estratega optimista y visionario.
            {historial}
            Propón ideas audaces y defiéndelas:"""
        }])['message']['content']
        historial += f"\nOPTIMISTA: {resp1}"
        
        # IA Crítica (Mistral)
        resp2 = ollama.chat(model='mistral:7b', messages=[{
            'role': 'user',
            'content': f"""Eres un analista crítico y pragmático.
            {historial}
            Identifica debilidades y propón mejoras realistas:"""
        }])['message']['content']
        historial += f"\nCRÍTICO: {resp2}"
        
        print(f"\n--- Ronda {i+1} ---")
        print(f"OPTIMISTA: {resp1}")
        print(f"CRÍTICO: {resp2}")
    
    return historial

debate("¿Cómo debería ESDATA diferenciarse de Inmuebles24 en el mercado de PropTech mexicano?")

from PIL import Image, ImageDraw, ImageFont
import os

def crear_flyer(foto_path, precio, descuento, direccion, output_path):
    img = Image.open(foto_path)
    draw = ImageDraw.Draw(img)
    w, h = img.size
    
    # Banner de precio (esquina superior derecha)
    banner_w, banner_h = 300, 80
    draw.rectangle([w-banner_w-20, 20, w-20, 20+banner_h], fill='#C41E3A')
    font_precio = ImageFont.truetype("arial.ttf", 36)
    draw.text((w-banner_w+10, 30), precio, fill='white', font=font_precio)
    
    # Banner de descuento
    if descuento:
        draw.rectangle([20, 20, 250, 70], fill='#FFD700')
        font_desc = ImageFont.truetype("arial.ttf", 24)
        draw.text((30, 28), descuento, fill='black', font=font_desc)
    
    # Banner inferior con dirección
    draw.rectangle([0, h-80, w, h], fill=(0,0,0,180))
    font_dir = ImageFont.truetype("arial.ttf", 20)
    draw.text((20, h-60), direccion, fill='white', font=font_dir)
    
    img.save(output_path)

PROYECTO 8: ENTRENAR IA / CREAR RED NEURONAL PROPIA

Concepto: Entrenar un modelo con tus conversaciones o crear una red neuronal con aprendizaje automático.

Aclaraciones importantes antes de empezar:

  1. Fine-tuning ≠ Entrenar desde cero. Entrenar un LLM desde cero cuesta millones de dólares. Lo que tú quieres es fine-tuning : tomar un modelo existente y ajustarlo con tus datos.
  2. Con tu hardware (3080 Ti 12GB): Puedes hacer fine-tuning de modelos de hasta ~7-8B parámetros usando técnicas de eficiencia (LoRA/QLoRA).
  3. ¿Vale la pena? En la mayoría de los casos, un buen prompt con RAG (Proyecto 2) da mejores resultados que fine-tuning, con mucho menos esfuerzo. Fine-tuning tiene sentido cuando:
    • Necesitas un estilo de respuesta muy específico y consistente
    • Tienes miles de ejemplos de conversaciones
    • Vas a usar el modelo miles de veces al día
TIER 1: LOW COST ($0)

Fine-tuning con Unsloth (gratis, optimizado para tu GPU): Unsloth es una librería que hace fine-tuning 2x más rápido y usa 60% menos memoria que los métodos tradicionales.

pip install unsloth

Preparar datos (formato de conversaciones):

[
  {
    "instruction": "Un cliente pregunta sobre precio de departamento en Providencia",
    "input": "¿Cuánto cuesta el depa de 2 recámaras?",
    "output": "¡Hola! El departamento de 2 recámaras en Col. Providencia arranca desde $2,850,000 MXN en preventa con 10% de descuento. ¿Te gustaría agendar una visita? Tengo disponibilidad esta semana."
  },
  // ... cientos de ejemplos más
]

Script de fine-tuning:

from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Qwen2.5-7B-Instruct",
    max_seq_length=2048,
    dtype=None,  # Auto-detecta
    load_in_4bit=True  # QLoRA - reduce VRAM de 14GB a ~6GB
)

model = FastLanguageModel.get_peft_model(
    model,
    r=16,  # Rank de LoRA
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
)

# Entrenar
from trl import SFTTrainer
from transformers import TrainingArguments

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,  # Tu dataset preparado
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        warmup_steps=5,
        max_steps=100,
        learning_rate=2e-4,
        fp16=True,
        output_dir="outputs",
    ),
)

trainer.train()
model.save_pretrained_gguf("modelo_century21", tokenizer, quantization_method="q4_k_m")

Resultado: Un archivo .gguf que puedes cargar en Ollama:

ollama create century21 -f Modelfile
ollama run century21

Tiempo estimado: ~1-3 horas de entrenamiento en tu 3080 Ti para 500 ejemplos.

TIER 1: LOW COST ($0)

Método del loop infinito con Ollama (inspirado en el experimento del compilador C de Anthropic): El investigador Nicholas Carlini de Anthropic usó 16 agentes Claude corriendo en paralelo durante 2,000 sesiones sin intervención humana para construir un compilador de C. La técnica es simple: meter la IA en un loop.

#!/bin/bash
# loop_agente.sh
while true; do
    LOGFILE="logs/agent_$(date +%Y%m%d_%H%M%S).log"
    ollama run qwen2.5:14b "$(cat TAREA_AGENTE.md)" > "$LOGFILE" 2>&1
    echo "Tarea completada, buscando siguiente..."
    sleep 5
done

TAREA_AGENTE.md:

Eres un agente autónomo de análisis inmobiliario.

TU TAREA ACTUAL:
1. Lee el archivo tareas_pendientes.txt
2. Toma la primera tarea no completada
3. Ejecuta el análisis
4. Guarda el resultado en resultados/
5. Marca la tarea como completada
6. Si hay más tareas, continúa. Si no, escribe "TODAS_COMPLETADAS"

REGLAS:
- Si algo falla, documenta el error y pasa a la siguiente tarea
- Nunca te detengas a preguntar, toma decisiones razonables
- Registra todo en el log

Limitación: Ollama local es más lento y menos inteligente que los modelos cloud. Para tareas simples y repetitivas funciona bien, pero para razonamiento complejo necesitas Tier 2 o 3.

GLOSARIO DE TÉRMINOS

  • LLM: Large Language Model — modelo de IA que entiende y genera texto
  • VRAM: Memoria de tu tarjeta gráfica, determina qué tan grande puede ser el modelo
  • Token: Unidad de texto (~4 caracteres). Los modelos cobran por token procesado
  • RAG: Retrieval-Augmented Generation — la IA busca en documentos antes de responder
  • Fine-tuning: Ajustar un modelo existente con tus propios datos
  • LoRA/QLoRA: Técnicas para hacer fine-tuning usando poca memoria
  • Embeddings: Representación numérica de texto que permite buscar por similitud
  • Vector DB: Base de datos que almacena embeddings para búsqueda rápida
  • MCP: Model Context Protocol — estándar para que IAs se conecten a herramientas
  • Agente: IA que puede tomar acciones (no solo chatear), como ejecutar código o navegar web
  • Orquestación: Coordinar múltiples IAs/herramientas para completar una tarea compleja
  • Docker: Software que empaqueta aplicaciones en contenedores aislados
  • Webhook: URL que recibe datos automáticamente cuando ocurre un evento
  • API: Interfaz para que programas se comuniquen entre sí
  • GGUF: Formato de archivo para modelos optimizados para correr localmente
  • Quantización: Comprimir un modelo para que use menos memoria (a cambio de algo de calidad)
